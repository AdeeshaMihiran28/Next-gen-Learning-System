SEMANTIC GRADING MODELS — EXPLANATION
======================================
Project : Voice Answering Questions (ICT Short Answer)
File    : Backend/voicemodel.py
Date    : 2026-04-07


==============================================================
OVERVIEW — WHY TWO MODELS?
==============================================================
The old grading system only matched keywords.
Problem: "I don't know something about system and hardware"
→ got marks just because the words "system" and "hardware" appeared.

Two new AI models fix this:
  Model 1 — checks MEANING similarity (semantic)
  Model 2 — checks if the student's answer actually MEANS the
             same thing as the ideal answer (NLI)

Both models work on TEXT only.
They do NOT touch audio or voice confidence at all.


==============================================================
MODEL 1 — all-mpnet-base-v2
==============================================================
Full name   : all-mpnet-base-v2
Type        : Sentence Transformer (SBERT)
Made by     : Hugging Face / UKP Lab
Size        : ~420 MB
Source      : https://huggingface.co/sentence-transformers/all-mpnet-base-v2

WHAT IT DOES:
  Converts a sentence into a vector of 768 numbers.
  These numbers represent the MEANING of the sentence.
  Two sentences with similar meanings will have vectors
  that point in the same direction.

HOW IT IS USED HERE:
  Step 1 — Convert student answer into a 768-number vector.
  Step 2 — Convert ideal answer into a 768-number vector.
  Step 3 — Measure cosine similarity between the two vectors.
  Result — A score from 0.0 to 1.0.
           0.0 = completely different meaning
           1.0 = identical meaning

EXAMPLE:
  Student : "Software that controls the computer hardware"
  Ideal   : "System software that manages computer hardware"
  Score   : ~0.88  (high — similar meaning, different words)

  Student : "The weather is nice today"
  Ideal   : "System software that manages computer hardware"
  Score   : ~0.04  (near zero — completely different topic)

WHY THIS MODEL specifically:
  - Best performing general-purpose sentence model on SBERT benchmarks
  - Trained on 1 billion+ sentence pairs
  - Works well for short technical answers (1-3 sentences)
  - Fast enough to run per-request without GPU


==============================================================
MODEL 2 — cross-encoder/nli-deberta-v3-small
==============================================================
Full name   : cross-encoder/nli-deberta-v3-small
Type        : Cross-Encoder / Natural Language Inference (NLI)
Made by     : Hugging Face / UKP Lab
Size        : ~180 MB
Source      : https://huggingface.co/cross-encoder/nli-deberta-v3-small

WHAT IS NLI?
  Natural Language Inference is the task of deciding whether
  one sentence LOGICALLY FOLLOWS from another.

  Given:
    Premise   = student's answer
    Hypothesis = ideal answer

  The model outputs 3 probabilities:
    - ENTAILMENT   : student answer means the same thing  ✅
    - NEUTRAL      : student answer is vaguely related    ➖
    - CONTRADICTION: student answer means the opposite    ❌

HOW IT IS USED HERE:
  We take only the ENTAILMENT probability as the NLI score.
  Score range: 0.0 to 1.0

  This score does two jobs:

  Job 1 — NLI GATE
    If nli_score < 0.20:
      keyword contribution is BLOCKED (set to 0.0)
    This stops wrong answers from getting marks just because
    they accidentally contain matching keywords.

  Job 2 — DIRECT SCORE CONTRIBUTION
    NLI score carries 55% weight in the final formula.
    It is the most important factor.

EXAMPLE:
  Student : "It holds data only when the computer is on"
  Ideal   : "Volatile memory maintains data while device is powered"
  NLI     : entailment ~0.85  → PASS gate → adds to score

  Student : "RAM stores data permanently on the hard disk"
  Ideal   : "Volatile memory maintains data while device is powered"
  NLI     : entailment ~0.03  → FAIL gate → keywords blocked

WHY THIS MODEL specifically:
  - DeBERTa-v3 is state-of-the-art for NLI tasks
  - "small" version chosen for speed (still very accurate)
  - Cross-Encoder reads BOTH sentences together for better
    understanding than independent encoding
  - Reliable entailment signal even for paraphrased answers


==============================================================
FINAL GRADING FORMULA
==============================================================

  keyword_score = 0.70 × ideal_coverage
                + 0.25 × main_keyword_coverage
                + 0.05 × optional_keyword_coverage

  gated_keyword = keyword_score   if nli_score >= 0.20
                = 0.0             if nli_score <  0.20

  final_score   = 0.30 × semantic_similarity   (Model 1)
                + 0.55 × nli_entailment         (Model 2)
                + 0.15 × gated_keyword          (keyword)

  marks = round(final_score × 10)


WEIGHT REASONING:
  NLI (0.55) is highest because it directly checks meaning.
  Semantic (0.30) supports NLI with a softer similarity signal.
  Keyword (0.15) is now just a small bonus, not the main driver.


==============================================================
GRADING LEVELS
==============================================================
  marks >= 8  →  GOOD
  marks >= 5  →  PARTIAL
  marks >= 3  →  WEAK
  marks <  3  →  INCORRECT


==============================================================
FALLBACK BEHAVIOR (if models fail to load)
==============================================================
  Both models loaded   → Full hybrid formula (above)
  Only Model 1 loaded  → 0.60×semantic + 0.40×keyword
  No models loaded     → keyword-only (original system)

  The system never crashes. If models are missing it falls
  back automatically and still grades using keywords.
